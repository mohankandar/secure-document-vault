## What to build

1. Two new Business administration tabs: **Legal holds** (after Keeping documents) and **Approvals** (last, with the count of waiting requests).
2. **Approvals:** compact one-line rows; scope icon (one sheet = one document, stack = whole contract), received date and pages on hover; grouped by contract with "Approve all" per group; **groups collapse and expand** by clicking the heading (chevron), collapsed by default when more than 10 requests are waiting, expanded otherwise; a collapsed heading shows the request count, kinds and requesters; its checkbox selects the whole group and the summary bar lists exactly what is included; a group holding a whole-contract request stays expanded; filter chips by request type with counts, requester filter, oldest first; tick and approve or decline in bulk with the summary bar. Whole-contract requests can't be ticked and show "Review". Footer: expiry note and "Decided recently".
3. Only the primary identifier, received date, page count, level, requester, reason and time are shown. Never the internal document ID, titles, names or content.
4. **Legal holds:** place a hold by contract number with a reason (shows how many documents it covers, without showing them); list of active holds with Release.
5. Keeping documents gains one line: "N documents on legal hold".
6. **Audit filter by level** (owner approves the small server change by giving this task): the Audit screen gets a "Sensitivity" filter (Any, Confidential, Highly Confidential), so compliance can ask "who opened Highly Confidential documents this month". The audit events from tasks 0024–0028 already record the level; add the filter to the audit query.
7. **In-app notices for requesters:** when a request is approved, declined or expires, the requester sees a count on the Requests tab and a short notice when they next open Vero. Email, Teams and Slack come later through the shared notification module.
8. **Any Business admin of the entity can decide a request.** Make sure nothing assumes a single Business admin.

## Error codes (owner decision 2026-11-20, applies to every refusal in this task)

Every user-facing refusal or error returns a short, stable **code** plus a plain **message** in the error body, e.g. `{"code":"SDV-SEN-001","message":"This document is restricted."}`. Format: `SDV-<AREA>-<NNN>` (SDV = product; AREA = three letters such as SEN sensitivity, ROL roles, HLD legal hold, APR approvals, INT intake). Codes never change meaning once released. Each code is listed in `docs/api/error-codes.md` with: meaning, what the user should do, and what support should tell the customer. Other apps (for example the Platform Console runbook) read that list.
