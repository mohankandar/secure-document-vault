Written: 2026-11-20, from the Platform Console thread's brief, adjusted by the SDV design chat. Branch: `docs/failure-catalog`, taken from the **last branch of the V1 series** (`feature/reports-2`, after task 0033), not from `release/vero-r7`, so the catalog covers the sensitivity, approvals, legal hold, duplicates and reports code and builds on the existing `SDV-SEN-…` / `SDV-ROL-…` codes. Do not push or merge.

**ANALYSIS ONLY. Do not change any code.**

## Goal

A complete failure catalog from the code, so every failure says exactly what failed, why, and what to do. Never "an error occurred" or a raw exception.

1. Go flow by flow: start-up and setup; sign-in; intake (API, watch folder, polling); processing, storage and encryption; viewing, search, print, download; sensitivity, approvals, legal holds, duplicates; reports; admin screens; anything outbound.
2. List every point where something can fail (thrown, caught, returned, or swallowed). For each one record:
   - file:line and flow
   - what triggers it
   - today's message and code (if any)
   - kind: never reached us / reached but refused / accepted then failed / needs a person / not authorised / restricted / not found / authorised but system failed / outside dependency down
   - proposed code `SDV-<AREA>-<NNN>` (**keep every code already released in `docs/api/error-codes.md` unchanged**; new codes continue each area's numbering)
   - message the user sees (safe, actionable)
   - exact cause for the IT Admin and the log
   - fix
   - what L1 support tells the customer
   - generic today? (yes/no)
3. List every outside dependency (database, Vault/key service, secret store, storage, login hub, etc.) and say whether start-up checks it today, and how.
4. Rules: messages and logs never hold passwords, keys, tokens, document content or redacted values. User sign-in messages never reveal whether an account exists. Every logged failure should carry a reference ID; note where it doesn't today.

## Output

- `docs/api/error-codes.md`: the full catalog, added to the existing codes.
- `docs/work/0034-report.md`: counts per flow, every generic one, top risks, and proposed fix tasks grouped by flow.
