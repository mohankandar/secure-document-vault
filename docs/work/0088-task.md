# 0088: Keycloak set-up for `sdv-web` and the real browser sign-in check

Written 2026-11-24 by the design chat; **rewritten 2026-11-24**: the `dev-automation` client is not used (Keycloak 26.8.2 answers 401 on its admin API). Instead, a script **the owner runs with his own admin login**, the way LexaVault's `Setup-LexaVaultTestUsers.ps1` does (read it for the pattern only; copy no product name). Branch `chore/keycloak-check` from `release/vero-r7`.

**Part A (session):**
1. `Set-SDV-DevKeycloak.ps1`, run by the owner: asks for the Keycloak admin user and password at the prompt (never stored, never printed, never on the command line), works only on `http://localhost:8181`, realm `document-platform-local`; refuses any other realm or the master realm's clients. It sets client `sdv-web` (public, standard flow only, PKCE S256, redirect `http://localhost:5183/`, web origin `http://localhost:5183`) and one test user per Vero role in the groups the demo seed expects, plus one user with no mapped group. Idempotent: a second run says "nothing changed".
2. Test users get generated passwords, written only to `C:\dev\sdv\dev-test-users.properties` (outside the repo, this Windows user only). Local development accounts for demo data only; never printed, logged or committed.
3. Prove the script against a **scratch Keycloak container** of the same version (own name and port; removed after if allowed, else left for the owner with the exact `docker rm` command). Never `lexa-keycloak` from a session.
4. `Test-SDV-KeycloakLive.ps1`: reads the test users from that file, starts Vero on a scratch database against `lexa-keycloak`, and checks in a real browser: sign in, refresh, open a document, sign out; the user with no group is refused; a token from another client is refused. If the file isn't there, it stops and says the owner's step is open.
5. Merge Part A on green `ci-passed`; the report gives the owner's exact command. Mark the item `stopped: owner (run Set-SDV-DevKeycloak.ps1)`.

**Part B (when `C:\dev\sdv\dev-test-users.properties` exists):** run `Test-SDV-KeycloakLive.ps1`, which is also the "live Keycloak delivery" owed by 0065, 0067 and 0070. Report in the same file. Later tasks run it where their task file asks.
