## What to build

1. **Results rows:** records show as today. A small lock icon next to the record identifier when the record holds documents this person can't open (`restrictedLevel`): dark = Highly Confidential, light blue = Confidential. Accessible label on the icon.
2. **Record panel:** restricted documents as locked items with the level badge; "Contract level" box with a **Level** button for Document stewards and Restricted stewards only (hidden for others, not greyed).
3. **Viewer:** level badge next to the title. For Highly Confidential: "Request download" and "Request print" instead of Download and Print; once approved, the button reads "Download (approved, use by …)" and works once. Requests tab with the person's own requests and their state. **Level** button opens the dialog.
4. **Level dialog:** "Apply to" choice (from the viewer "This document" is preselected; from the record panel "Whole contract"). Raise applies at once with a reason; lower shows "Needs approval" and creates a request. Warning when the person will lose access after raising. Button wording follows the choice.
5. Opening a locked document shows a short "You can't open this document" message that reveals nothing else.

## Error codes (owner decision 2026-11-20, applies to every refusal in this task)

Every user-facing refusal or error returns a short, stable **code** plus a plain **message** in the error body, e.g. `{"code":"SDV-SEN-001","message":"This document is restricted."}`. Format: `SDV-<AREA>-<NNN>` (SDV = product; AREA = three letters such as SEN sensitivity, ROL roles, HLD legal hold, APR approvals, INT intake). Codes never change meaning once released. Each code is listed in `docs/api/error-codes.md` with: meaning, what the user should do, and what support should tell the customer. Other apps (for example the Platform Console runbook) read that list.
