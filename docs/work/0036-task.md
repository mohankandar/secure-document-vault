# Task 0036: Error plumbing (failure-catalog fix 1)

Written: 2026-11-21, by the design chat. Branch: `fix/error-plumbing`, taken from `release/vero-r7`. Backend only; no schema change (stop and ask if one is needed).
Source: report 0034, "Proposed fix tasks" item 1 and "Top risks" 1–3; owner answers in `0034-owner-answers.md`. The other fix tasks build on this one.

## What to build

1. **Last-resort error handler.** Every error leaving Vero, including ones no handler catches today (storage, Vault, database, and Spring's own refusals: bad UUID, bad JSON, missing header, wrong content type), returns one body:
   `{"code": "SDV-…", "message": "<plain, safe>", "reference": "<id>", "timestamp": "<UTC>"}`.
   Never a stack trace, exception class, SQL, path, token, key, document content or redacted value.
2. **A reference in every error body**, the same ID written to the log line and, where an audit event is written, to the event.
3. **One ERROR log line with the reference for every 5xx**, and a WARN line for refusals that need a person (as the catalog marks them). The log line holds the exact cause for IT; the body holds only the safe message.
4. **Status mapping (approved in `0034-owner-answers.md`, item 5):**
   - `DataAccessException` → 503, SYS-014;
   - Spring MVC request errors → 400, SYS-015;
   - internal checks: a new `InternalCheckFailed` type (500, SYS-016 / SYS-017) replaces `IllegalStateException` for internal checks, so they are no longer sent as 409;
   - "no storage space" → 503, STO-001.
5. **Codes:** move the codes this task sends from `####` (proposed) to `###` (released) in `docs/api/error-codes.md`, with their user message, IT cause and support line. Replace today's own codes touched here with SDV codes (owner answer 3); update `problemWords.ts` / `auditWords.ts` only if they read a code this task changes.
6. Update the OpenAPI file: the common error body on every operation.

## Tests

One test per mapping above (status, code, body shape, reference present, no forbidden content); a test that the reference in the body matches the log line; existing error tests updated only where this task changes the code or status (list them). Full build and `ui:capture`.
