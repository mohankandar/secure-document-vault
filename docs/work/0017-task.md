# Task 0017: Records picks the right sending system

Written: 2026-11-18, by the design chat, after report 0013. Branch: `fix/records-source-choice`, taken from `feature/install-1`.

## The problem (from report 0013)

The leftover paused source "Tour test system 20261118181639", which has no search fields, is sometimes picked by the Records search instead of LexaVault, so searches fail. A customer can have a paused or half-set-up sending system too, so this is a product bug, not only a test problem. **Keep that leftover source: it is the test case.**

## Who sees this

| Part | Seen by |
|---|---|
| Which sending system Records searches | Business user, Document steward |

## What to build

1. **Find the cause** and say it in the report (for example list order not fixed, or a race between loading sources and the search schema).
2. **One fixed rule for the default:** only sending systems that have at least one searchable field and at least one stored record can be the default; among those, the person's last choice in this browser, else the one with the most recent delivery, else by name. Same result every time for the same data.
3. **Sending systems with no searchable field are never offered** in Records' picker. Paused systems that hold records stay searchable (their documents are still there) but never become the default if an active one qualifies.
4. If no system qualifies, Records says: "There's nothing to search yet. Records appear here once a sending system delivers documents."
5. Home's search and Needs attention use the same rule.
6. Tour: choose LexaVault explicitly before searching, and add a test that with the leftover source present the default is still LexaVault, ten loads in a row.
