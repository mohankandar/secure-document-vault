# Task 0001: three quick UI fixes (prototype wording, real times, identifier box)

Written: 2026-11-17, by the design chat. The owner approved these changes on 2026-11-17 (SDV UI review, changes 1, 4 and 5). UI only: no backend change.

Branch: `fix/ui-quick-fixes`, taken from `release/vero-r7`.

This is the first task in this repository's `docs/work/` folder. `CLAUDE.md` at the root and `docs/work/README.md` were added by the design chat at the same time; commit them with this task.

## Part A: remove prototype wording from what customers see

1. The chip "R7 · business integration" (on phones "Simulated") in the top bar (`src/r7/Shell.tsx`, class `v-sim-chip`) shows in every build. Show it only in development (`import.meta.env.DEV`); never in a product build.
2. The browser tab title is "Vero R7 · Prototype" (`src/r7/entry.tsx`). Make it the product name only.
3. The product name may change. Put it in one place (a single constant, e.g. `PRODUCT_NAME = 'Vero'`) and use it for the tab title, the brand mark in the top bar, and the brand's accessible name. No other screen should spell the name itself.
4. The permanent redaction warning (`src/r7/Viewer.tsx`, "This permanently replaces the current PDF") starts "In production, …". Change the text to: "Marked areas are removed for every user and the original is not kept. Use this only to remove content that should never have been stored."
5. Search `src/r7/` for any other text a user could see in a connected session that says "simulated", "Simulated", "prototype" or "Prototype" (for example toasts such as "Comment added (simulated)", "(simulated)" in Tenant IT, the "simulated" badge in the audit list). For each one, find out whether it can be reached when the app is connected to the backend.
   - Reachable only without a backend (prototype mode) or only in development: leave it, and list it in the report.
   - Reachable in a connected session: do not change it in this task. List it in the report with the file and line, and say what really happens there (is the action sent to the server, or only pretended?). This matters more than the wording: a connected user must never be told something was saved when it was not.

## Part B: real times instead of "just now"

`fmtRel` in `src/r7/ui.tsx` measures time against the fixed prototype date `NOW` (15 Oct 2026) from `src/r7/data.ts`, so anything after that date shows "just now". Every search result currently says "Updated just now".

1. Make `fmtRel` use the current time.
2. Check every other use of `NOW` in `src/r7/`. Any that affects what a connected user sees must use the current time too. Uses that only feed prototype sample data can stay; list them in the report.
3. Times in the future (clock differences between server and browser) must still read sensibly, not as negative or odd values.

## Part C: the identifier box

In the record panel and in the viewer's left column, the identifier box (`.ws-ids` in `src/r7/r7.css`) is a two-column grid. With one identifier, the second half is an empty grey block, and in the viewer's narrow column a 12-digit contract number breaks over two lines ("3000000000" / "03").

Wanted:

1. One identifier fills the whole box. No empty grey half.
2. Two identifiers sit side by side in the record panel and stack one above the other in the viewer's narrow column.
3. A number up to 20 characters stays on one line in the viewer column at a 1440-pixel-wide window. If a value is longer still, shorten it with "…" and show the full value on hover and to screen readers; never break a number in the middle.
