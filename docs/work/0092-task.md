# 0092: Install guides read as a customer's IT would (docs only)

Written 2026-11-25 by the design chat. Side session; branch `docs/install-review` from `release/vero-r7`. **No app start, no containers, no local database.**

1. Read the install runbook, the IT Admin guide, the Business Admin guide, `SETUP.md` and the error codes as a customer's IT team would, from a new Windows server and a new Linux server, with their own Postgres, Vault and sign-in system (not ours).
2. For each step: is every prerequisite named (versions, ports, accounts, certificates, the Vault policies and AppRole, the sign-in client, licence file, backups and the erase log), is every command exact, is there a check that the step worked, and what to do when it fails?
3. Write `docs/work/0092-install-gaps.md`: a table of gaps (where, what is missing, severity: blocks install / causes a support call / cosmetic). Fix the obvious ones in the guides in the same PR (wording, missing commands that already exist in scripts); list the rest.
4. Never put a real host name, password, token or key in a guide. Report `docs/work/0092-report.md`. Merge on green `ci-passed`; if a guide changed meanwhile in the main session, merge `release/vero-r7` in (no rebase, no force-push).
