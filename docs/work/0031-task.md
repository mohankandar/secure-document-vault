## Owner decision (2026-11-20)

Three cases of "the same document arrives again":

| Case | What Vero does |
|---|---|
| 1. Retry of the same delivery (same request ID / idempotency key) | As today: "already received", original document, no second copy. No change |
| 2. **Same file, new delivery** (same tenant, same sending system, same record, same SHA-256 content checksum, different request ID) | **New:** do **not** store a second copy. Answer 200 with the existing document's ID and status `DUPLICATE_ALREADY_STORED`, record it, count it |
| 3. Same paper scanned again (different checksum) | Stored as a new document, as today. Not detectable; a business matter |

Today case 2 stores a second copy and only sets `duplicate=true` in the receipt (`DocumentIntakeService`, `hasExactDuplicateContent`). Replace that.

## What to build

1. **Detection** before anything is stored: same tenant + sending system + record (the record key from task 0024) + content SHA-256, and the existing document is not deleted.
2. **No second copy:** nothing is encrypted or written to storage for the duplicate; the receipt carries the existing document ID, `duplicate: true` and status `DUPLICATE_ALREADY_STORED`. The sender treats it as delivered (2xx), so it never retries or alerts.
3. **Submission completeness:** if the new submission expects documents (manifest), the duplicate fills its expected slot by pointing at the existing document, so "2 of 4 received" stays right. Say how you did it.
4. **Sensitivity:** if the duplicate carries a higher document level, raise the existing document (audited, as a source-system raise). A lower or equal level is ignored and audited. Record level follows task 0024 rules.
5. **Record it:** an audit event `DOCUMENT_DUPLICATE_RECEIVED` with request ID, sending system, record identifier, checksum and existing document ID; and whatever the Daily intake report (next task) needs to count duplicates per day and sending system and list them in its CSV.
6. The same file under a **different record** is stored normally (no flag): LexaVault will later verify contract numbers itself.
7. Update the OpenAPI file and `docs/api/README.md` with the new status. Add error codes only if a refusal is involved (none expected).
