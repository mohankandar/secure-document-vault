# 0100: Security fixes 5: approval links and recipient lists (VSEC-201, 203, 204, 208)

Written 2026-11-27 by the SDV design chat from 0096's report (fix group 1). Branch `fix/security-5-approvals` from `release/vero-r7`. **Tests first** for each finding; plain-terms commits (detail stays on the local review branch).

1. **VSEC-201:** Vero's own `ApproverCheck` bean: the person must hold the approver role in identity **now** (not "is on a list"). The link page checks the permission **before it shows anything**; someone who may not decide sees only "This request isn't yours to decide" (no who, why or which record) and the attempt is audited without the token.
2. **VSEC-203:** a role's recipient list accepts only users who hold that role in the entity; when a role is removed, that person is taken off every list of that role in the same transaction (audited as `NOTIFICATION_RECIPIENT_REMOVED`, reason role gone). Existing rows: a one-time clean-up in the changeset.
3. **VSEC-204:** the app address in messages comes from the install configuration only (`sdv.public-url`, https required unless the dev profile); the IT screen shows it read-only. Remove the edit.
4. **VSEC-208:** runbook and IT guide: keep the approval-link path out of web-server access logs (exact lines for IIS and nginx).
