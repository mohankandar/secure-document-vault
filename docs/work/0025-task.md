## 3. Separation rules

1. `RESTRICTED_STEWARD` can never be held together with `BUSINESS_ADMIN`, `TENANT_IT_ADMIN` or `PLATFORM_OPERATIONS_ADMIN`. Where roles are resolved from login groups (`SdvGroupRoleMapper` and the local-mode path), a user who would get both gets **neither** the Restricted Steward role **nor** the conflicting admin role, plus an audit event and a problem record visible to Tenant IT Admin. Fail closed.
2. The Business Admin's role-permission overrides (`tenant_role_capability_overrides`, Roles & permissions screen) must never give VIEW_CONFIDENTIAL, VIEW_HIGHLY_CONFIDENTIAL or REQUEST_SENSITIVE_ACCESS to Business Admin, IT Admin or Platform Ops, and never give APPROVE_SENSITIVE_ACCESS to a Steward or Restricted Steward. Refuse such overrides on the server with a clear message.
3. Any change to which login group maps to `RESTRICTED_STEWARD` is audited and creates a notice for the Business Admin.

## Error codes (owner decision 2026-11-20, applies to every refusal in this task)

Every user-facing refusal or error returns a short, stable **code** plus a plain **message** in the error body, e.g. `{"code":"SDV-SEN-001","message":"This document is restricted."}`. Format: `SDV-<AREA>-<NNN>` (SDV = product; AREA = three letters such as SEN sensitivity, ROL roles, HLD legal hold, APR approvals, INT intake). Codes never change meaning once released. Each code is listed in `docs/api/error-codes.md` with: meaning, what the user should do, and what support should tell the customer. Other apps (for example the Platform Console runbook) read that list.
