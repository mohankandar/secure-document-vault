# 0097: Install proof from the runbook, as a customer's IT would

Written 2026-11-27 by the SDV design chat. **After 0096 is merged.** Branch `chore/install-proof` from `release/vero-r7`.

**Approved:** a package script, guide fixes, and the smallest product fix (with a test) where the install is blocked. **Never touch** `sdv-postgres`, `sdv-vault`, `securedoc-postgres`, `lexa-keycloak`, `lexa-keycloak-db`; no `docker compose down`; never initialise, reset or reseal the real Vault.

1. **Package script** (0092 open gap 2, decided: yes): one command that builds the customer's package (backend, UI, setup command, service files for Windows and Linux, guides, checksums) into a versioned folder and zip. No test users, demo seed, keys, licence or host names inside; a check fails the build if any are found.
2. **Install from the package only**, following the runbook word for word, on fresh scratch containers with their own names and ports (`vero-install-*`): Postgres, a dev Vault, and a Keycloak with a new realm made from the IT guide's steps (not our realm export). Do it twice: Windows (this computer, as a service) and Linux (a plain Linux container, systemd or the guide's stated alternative; this closes 0092 open gap 11).
3. Every step the runbook gets wrong, leaves out or that needs our knowledge: fix the guide in this PR and record it in `docs/work/0097-install-log.md` (step, what happened, fix). Finish with the first entity activated, a Business Admin signed in, one document filed and found, health green, a backup taken and restored to a second scratch database.
4. Time the whole install and note it in the log (target: under two hours for a customer's IT).
5. Remove only the `vero-install-*` containers and scratch databases you made. Report `docs/work/0097-report.md`; merge on green `ci-passed`. 0092 open gap 7 (first-entity activation without a hand-made token) is 0098; if it blocks step 3, note the manual step and carry on.

6. **Also (from 0099, Q-3):** prove setup's sign-in change and roll-back once on the scratch database and scratch Vault: `plan`, `apply --replace-connection` with a second sign-in file, a sign-in works, then `rollback-login-connection`, the first one works again. Add the result to the install log.
