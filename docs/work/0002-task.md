# Task 0002: new top bar and account menu (remove the left icon strip)

Written: 2026-11-17, by the design chat. The owner approved the new Vero designs on 2026-11-17 (SDV UI review, change 2 and the agreed layout).

**Start only after report 0001 is written and the owner has approved it.** Branch: `feature/ui-top-bar`, taken from `fix/ui-quick-fixes` (task 0001's branch), so the two do not conflict in `Shell.tsx`.

## The design

Open `docs/design/vero-ui-after.html` in a browser. It holds all five approved screens. This task builds only the top bar (every screen) and the account menu (screen 5). Home, search, filters and viewer come in later tasks: leave their content as it is today, only under the new top bar.

The same pattern will be built in LexaVault later, so keep the top bar and account menu as self-contained components with no SDV-specific logic inside them (data in, events out).

## Part A: the top bar

From left to right, 56 px high, white, one line:

1. The brand mark (the product name from task 0001's single constant, with the green dot).
2. **Area tabs**: one text tab per area the person's role may open (today `role.areas`): for a business user "Records" only (Home arrives in a later task). The current area is highlighted as in the design. A person with several areas (e.g. the local administrator persona) sees several tabs.
3. Space.
4. The "Go to…" command box (Ctrl K), as today.
5. The **account button**: avatar with initials, the person's name, and below it "Organization · Entity" (entity only once SDV has entities; until then the organization alone). A chevron.

Remove:

- the left icon strip (`Rail` in `src/r7/Shell.tsx`) and its expand/collapse control and the `[` shortcut;
- the separate theme button in the top bar (theme moves into the menu);
- "Connected session" text and the login ID in the top bar.

The second-level tabs inside an area (e.g. Business administration's Users & access, Roles & permissions…) stay as they are.

## Part B: the account menu

Opens from the account button; closes on Escape, on a click outside, and after choosing an item. Contents, top to bottom:

1. Avatar, name, email (if known), and the role in plain words (e.g. "Business user", "Document steward").
2. **Entity**: leave a clearly marked slot in the component for an entity list (radio buttons, "Switching shows only that entity's records."). Do not show it in SDV yet; SDV has no entities today. Write in the report what SDV would need for it.
3. **Theme**: Light / Dark / System. System follows the computer's setting and is the default. Remember the choice in the browser.
4. **Sign out**, using the existing sign-out path for OIDC; in LOCAL mode it can be hidden.
5. **Development only** (`import.meta.env.DEV`): the local test role switch and the Design system link that today sit in the rail and the session drawer. Never in a product build.

It works by keyboard (Tab, arrows, Enter, Escape) and has proper accessible names.

## Part C: the person's name

The session (`GET /api/v1/session`, `SessionCapabilitiesController.SessionResponse`) has `subject` but no name or email, so the bar would show "local-business-user" or an Okta ID.

1. Add optional `displayName` and `email` to `SessionResponse`, read from the sign-in token's standard `name` and `email` claims. This small backend change is approved by the owner for this task.
2. If reading those claims means changing the Enterprise Identity library, stop and report instead: that library is shared with LexaVault.
3. When there is no name, show a readable fallback, never the raw subject in the bar: in LOCAL mode a name per test role (e.g. "Local business user"); in OIDC mode the email, else "Signed in".
4. Backend test for the new fields (present, and absent when the token has no such claims).

## Part D: phones

At phone width the top bar keeps the brand and the account button; the area tabs and Go to… move to the existing bottom bar. The bottom bar's "System" and "Session" buttons are development-only; in a product build they do not appear.
