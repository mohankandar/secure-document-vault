## The problem (from report 0006)

Every page image request writes `DOCUMENT_PAGE_VIEWED`. So pages fetched ahead of time are recorded, and every zoom step records every loaded page again (2 events per click on a 14-page document).

## What to build

A page image sent to someone's browser is real access, so it must stay recorded, including pages fetched ahead of time. What goes is the repetition, and what changes is the wording.

1. **One viewing, one record per page.** `GET …/viewer` (metadata) already writes `DOCUMENT_VIEW_OPENED`. Return that event's ID to the browser as `viewingId`.
2. Page requests send `viewingId`. The server writes a page event **only the first time** that page is sent for that `viewingId`, whatever the zoom. Later requests for the same page in the same viewing write nothing.
3. The server, not the browser, decides: it accepts a `viewingId` only if it is a `DOCUMENT_VIEW_OPENED` event by the same person, for the same document and tenant, from the last 8 hours. Otherwise (missing, wrong, too old) it records the page as today. A browser can never avoid the record by leaving the ID out.
4. Put the `viewingId` and the page number in the event's safe details. Use the audit index added in migration 018 (`tenant_id, actor_id, action, occurred_at`) to check for an earlier event; check the query plan.
5. **Wording:** in Audit, Activity and the humanized action labels, the page event reads "loaded page 3 of loan-agreement.pdf", not "viewed", because a page fetched ahead of time may not have been looked at. Keep the action code `DOCUMENT_PAGE_VIEWED` so earlier records still match.
6. Development builds open the viewer twice (React's development mode). That is fine; the product build must write one open.

## Rules

## Checks

1. Tests: same viewing + same page twice = 1 event; different zoom = still 1; another person's or another document's `viewingId` = recorded normally; no `viewingId` = recorded normally; `viewingId` older than 8 hours = recorded normally.
2. Product build, steward, the 14-page demo document: open, scroll through 5 pages, zoom 3 times. List the events written: expect 1 open and one page event per page sent (including pages fetched ahead), none from zooming.
3. Full build with tests; `npm run typecheck`, `npm run build`, `npm run ui:capture`.
