# 0059: Spring Boot 4.2

Written: 2026-11-23, by the design chat. Board: LV-18 (owner approved). Vero moves off Spring Boot 3.5 (past open-source support) to **Spring Boot 4.2** (Spring Framework 7.1, Spring Security 7; newest 4.2.x patch at the time). Java stays 21. Its own task, never combined with integrating platform-core's integration release.

## Part A: plan (read only; can run now)
Branch `plan/spring-boot-4` from `release/vero-r7`. Change no code. Write `docs/work/0059-plan.md`:
1. Every change Vero needs, from Spring's official 4.0, 4.1 and 4.2 migration guides and release notes (cite them): removed or renamed APIs and properties Vero uses, Spring Security 7 configuration (Vero's security chains, JWT resource server, sign-in), Jackson 3, Hibernate/JPA if used, Liquibase, Actuator health groups and the readiness/busy rules, test changes (MockMvc, `@MockBean` replacements), Testcontainers, and each third-party dependency's 4.2-compatible version (PDFBox, Liquibase, Flyway, HikariCP, the HTTP clients; remove the 0058 override if 4.2's versions are newer).
2. Anything that blocks 4.2 today (a dependency without a 4.2-compatible release), each with a proposal.
3. The order of work and how CI proves each step.
4. **Platform-core:** Vero can't finish the move until platform-core publishes its 4.2 release (LV-18). List what Vero expects from it.
Stop after the plan.
