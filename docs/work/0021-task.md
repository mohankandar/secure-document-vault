# Task 0021: Remove prototype and old code

Written: 2026-11-19, by the design chat (backlog item "prototype-code cleanup"). Branch: `chore/remove-prototype-code`, taken from `release/vero-r7`.

## Why

The product always runs against the server: real sign-in in a customer install, and the local test sign-in in local mode. Code that only runs **without** a server session (fixtures, "simulated" comments, tags and redactions) never runs, but every change has to work around it. The old R5 app is still in the product bundle behind `?app=r5`. Removing both makes later changes safer and the product smaller. **Nothing on screen should change.**

## Who sees this

Nobody sees a change. Every role must look and behave exactly as before.

## Part A: R7 prototype paths

1. Remove every branch that runs only without a server session (`!liveSession` and similar): fixtures and simulated actions in `Viewer.tsx` (simulated comments, tags, redactions, `addDocActivity`, the "Possible sensitive identifier" sample callout, "policy v… at ingestion"), `store.tsx` (the prototype role switch, simulated activity), `Workspace.tsx`, `Home.tsx` and `Shell.tsx`.
2. Remove the prototype fixtures in `data.ts` (`RECORDS`, `PAGE_TEXT`, `RETENTION`, `RETENTION_SWEEP`, sample people and anything else only they use). Keep shared types and the role definitions if the live code uses them; move what's left to sensible places if `data.ts` becomes only types.
3. With no session, the app shows sign-in (or the existing error page), never fixture data.
4. Keep: local mode and its test sign-in and role switch, the development-only Design system page, the "Later release" markers in development builds, `ui:capture` and `ui:compare`.

## Part B: the old R5 app

1. Remove `?app=r5` from `main.tsx`, and delete the files only R5 uses: `legacy-entry.tsx`, `App.tsx`, `BusinessWorkspace.tsx`, `AdminKit.tsx`, `PdfViewer.tsx`, `Icon.tsx`, and the stylesheets only R5 imports (`styles.css`, `ui-foundation.css`, `business-workspace.css`, `admin-framework.css`, and `tokens.css` if R7 doesn't use it). Check each file first: delete it only if nothing R7 uses imports it.
2. In `api.ts` and `auth.ts` (shared with R7), remove exports only R5 used.
3. Remove R5 mentions from docs that describe how to run the app (not from old reports or history).

## Rules

- **The owner approves deleting** the files listed above and any other file under `frontend/sdv-ui/src` that this task leaves unused, once nothing refers to it and the checks pass. List every deleted file in the report.
- Frontend only. No backend change. No new dependencies.
- If something looks prototype-only but a live path uses it, keep it and say so.

## Checks

1. `npm run typecheck`, `npm run build`, `npm run ui:capture`, `npm run ui:compare` (all 19 boards must still pass: proof nothing visible changed).
2. Report the size of the production bundle before and after.
3. Search the built bundle for "simulated", "Simulated", "r5" and fixture names (for example "Jordan Ellis" from the old fixtures); report what's left and why.

Commit on `chore/remove-prototype-code`. Do not push or merge.

What was removed (file list), bundle size before and after, check results, anything kept and why, anything the owner must decide.
