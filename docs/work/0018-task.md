# Task 0018: Main screens look exactly like the canvas

Written: 2026-11-18, by the design chat, after the owner's first look-and-feel test. Branch: `fix/match-canvas-main`, taken from `fix/records-source-choice`.

## Why

The owner tested the look and feel. Every screen works, but **it does not look like the approved canvas**: different page width, layout, spacing, type sizes, card styles and wording. Earlier tasks described features and pointed to the design but never required a visual match. This task does.

**The standard: a close visual match to the canvas.** Same layout and page width, same spacing, type sizes and weights, colours, borders and radii, same components in the same places, same wording. Only real data may differ (a name's length, how many rows).

## The reference

`docs/design/vero-ui-after.html`, the approved main screens: Home, Search results with the record panel, Filters, Viewer, Account menu. The canvas is the source of truth; where this conflicts with an earlier task's wording, follow the canvas and list it in the report.

Not copied from the canvas: the blue "Seen by" tags (design notes only), and anything marked "Later release" in the product build (development markers stay as they are).

## What to do

1. **Build a comparison tool first** (`npm run ui:compare`, Playwright, no new dependency):
   - it opens the canvas file and screenshots each screen's app frame at 1440 px;
   - it puts the app in the same state (same role, same record, same panel open) and screenshots it at the same size;
   - it writes side-by-side images (canvas left, app right) to `.runtime/ui-compare/<screen>.png`.
2. **Take the canvas's styles as the app's tokens:** font family, sizes and weights, colours, spacing, radii, borders and shadows. Read them from the canvas file's CSS. Put them in the app's design tokens, so every screen uses them rather than one-off values.
3. **Rework each screen until it matches:**
   - **Home:** full-width layout as on the canvas; one search box with Filters and Search inside it; the subtitle; Recently viewed rows with number, full record title, type and time; Needs attention as the highlighted card with a sentence ("Only 2 of 4 documents have arrived. The rest are still coming from the loan system.").
   - **Search results:** the record title (name), preview fields and status exactly as drawn. The record panel header is the record title, not the identifiers joined together.
   - **Filters, Viewer, Account menu:** as drawn.
   - Dark mode and 390 px follow the same tokens. The canvas only shows desktop light, so keep the current phone layout behaviour and make it consistent.
4. **Demo data that looks like the canvas** (local seed only, never in a product start):
   - organization "Acme Lending", unit "Mortgage";
   - full borrower names and a loan type on every demo record;
   - local test people with full names (for example Maya Okafor as Business user, Daniel Reyes as Document steward).

   Record 100000000001 must show a name, not "—". Use the Record title setting from task 0009 so titles are full names.
5. **Difference list:** for each screen, a table of every difference you can still see between canvas and app, and why each remaining one is allowed (real data only). The task is done when nothing else is left.

## Rules

- Frontend and local demo data only. If a match needs data the server doesn't send (for example the type shown in Recently viewed), stop and report which field.
- No new dependencies.
- Don't change behaviour that earlier tasks built (search routing, permissions, audit).

## Checks

1. `npm run typecheck`, `npm run build`, `npm run ui:capture` passes.
2. `npm run ui:compare` images for Home, Search results with record panel, Filters, Viewer and Account menu, for the owner to look at.
3. A product-build check: no development markers, nothing from the canvas notes.

Commit on `fix/match-canvas-main`. Do not push or merge.
