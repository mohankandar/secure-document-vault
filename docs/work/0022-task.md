## Part A: server

1. `POST /api/v1/business/search` accepts `anywhere` (text, 2 to 100 characters after trimming). It counts as a criterion, so it works alone or with fields, dates and `incompleteOnly`, combined with AND.
2. `anywhere` matches a record when **any searchable field** of the chosen sending system matches it, each field with **its own match** (exact, starts with, contains) and normalization:
   - digits-only fields are tried only when the text has digits;
   - date fields are skipped (dates stay in Filters);
   - fields the Business admin made unsearchable are never tried.
3. Each result carries `matchedFields`: the label and value of every field that matched. Values come from the record's own data, which the person is already allowed to see.
4. **Best match first** when `anywhere` is used: exact identifier match, then exact on other fields, then starts with, then contains; ties by last updated. Other searches keep sorting by last updated.
5. Same permissions, paging and audit as search today. The audit entry says it was an "anywhere" search, with the count.
6. Tests: each match kind; a digits-only field skipped for letters; unsearchable and date fields never matched; `matchedFields` correct; ordering; combined with a date range; too short or too long refused; tenant isolation.
7. Check the query plan on the development data and report it. If "contains" across many fields is slow, say so; faster name search (`pg_trgm`) is a separate backlog item, don't add it here.

## Part B: screens (match the two boards)

1. **Typing** (Home and Records search box): after 2 characters, a list opens under the box:
   - **Search everywhere for "…"**, highlighted, runs on Enter;
   - **Or only in one field:** one row per searchable field that can match what was typed, worded with its match ("Borrower contains "patel"", "Loan type is "patel""). Picking one runs today's field search and shows today's field chip;
   - **Records you opened recently** that match, from the existing Recently viewed data (no new server call, nothing new audited). Clicking opens the record as Home does.
   - Arrow keys move, Enter picks, Escape closes. It works on phones as a full-width list.
2. This replaces today's routing (digits to the identifier, text to the name) and the "Search it as … instead" suggestion; a typed contract number still comes first because exact identifier matches rank first.
3. **Results:**
   - the chip reads "Anywhere: patel";
   - the heading reads "4 records · "patel" in any searchable field · <sending system>", and the sort label reads "Best match first";
   - the matching text is marked in the row, the record panel's Details and the "Matched …" line;
   - when the match is in a field that isn't a column, one line under the title says "Matched Co-borrower: Priya Patel".
4. Filters and date ranges work alongside it, as today.
