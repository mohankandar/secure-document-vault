# 0062: Security fixes 1 (sign-in, request size, audit, storage paths, errors)

Written: 2026-11-24 by the SDV design chat (LV-19: decided as recommended). Branch `fix/security-1` from `release/vero-r7`. Vero-only.

The findings are in `C:\dev\sdv\queue\0061-security-findings.md` (local only, outside the repo). **The repository is public:** in commits, PR text and this report describe the fixes in plain terms, never how to use an unfixed weakness, and never copy the findings file into the repo.

**Approved:** code, config and test changes; a Liquibase changeset only if needed; new codes. No new dependency.

1. **VSEC-1** machine tokens: a bound client's token counts as a machine only if it carries no user-only claims (`sid`, `auth_time`, `nonce`, `at_hash`, `acr`) and, where the login system marks client-credentials tokens (Keycloak `azp` = `sub` service account, Okta/Entra `idtyp=app` or equivalent), that mark is present. Add a per-connection setting naming the required claim and value; default: refuse user-only claims. Live check with the local Keycloak: a client-credentials token works; a person's token through the same client is refused.
2. **VSEC-5** body limits: a filter before the controllers limits every non-PDF request body (1 MB default; submissions configurable), by `Content-Length` and by counting while reading; Jackson's own document limits as a second line. Answered with a coded 413.
3. **VSEC-6** redaction reason: kept only in the redaction tables; the audit event holds an ID. Existing events: filter `reason` and `regions` out on every way out (audit page, activity, exports, sealed report); rows are not changed.
4. **VSEC-7** storage paths: an installer setting `sdv.storage.allowed-roots` (empty = only the default data folder); refuse paths outside it, UNC and device paths, and links; the same answer for "another entity's" and "not allowed". Document it in the install runbook.
5. **VSEC-18** error answers: only Vero's own coded messages reach the caller; any other exception gets the generic coded answer (the detail stays in the log with the reference).
6. **VSEC-19** references: Vero always makes the reference; a caller's `X-Correlation-Id` is kept as a separate field in logs and audit.
7. **VSEC-16** (decided): add Business Admin + Document Steward, and IT Admin + any document role, to the separation rules (the design says admins never open documents); conflicts withheld and recorded as today.

Tests for each; full build, both schema checks, `npm test`, `ui:capture`. Report `docs/work/0062-report.md` with "No other product's name or behaviour in code". Merge on green `ci-passed`.
