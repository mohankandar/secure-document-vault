## Part A: list everything in a date range (owner request)

1. In Filters, two date ranges, each with visible **From** and **To** labels:
   - **Received**: the server's `dateFrom` / `dateTo` (the search service calls them `createdFrom` / `createdTo`). Check in the backend which record date they filter on, and use that meaning in the label and in the report.
   - **Last updated**: `lastUpdatedFrom` / `lastUpdatedTo`, as today.
2. Quick buttons beside each range: Today, Last 7 days, Last 30 days, This month.
3. A date range alone is enough. With no other field, Show results lists every record in that range, 25 per page with Next and Previous. The server already allows this; remove any screen check that demands another field.
4. Each range shows as a chip in the search bar ("Received 1 Nov – 15 Nov ×").

## Part B: name search ignores upper and lower case (backend change, approved by the owner)

1. Contains and Starts with matches ignore case on the server: "pat" finds "Patel". Exact matches keep their configured normalization.
2. Check that the query still uses an index on a large table (for example an index on the lower-cased value). If that needs a database migration, stop and ask first, as `CLAUDE.md` requires.
3. Backend tests for both cases (found with different case; exact fields unchanged).

## Part C: a helpful suggestion when the box finds nothing

When a number typed in the box finds nothing as the first identifier, and the source has another identifier that accepts the same input, the empty result says so and offers one click: "No contract number 123456. Search it as member number instead". No automatic second request.

## Part D: tests fail when demo data is missing

The e2e record steps fail with a clear message ("No demo records: run Seed-SDV-Demo-Records.ps1") instead of being skipped. An explicit environment variable (for example `SDV_E2E_ALLOW_NO_DATA=1`) may skip them on purpose.
