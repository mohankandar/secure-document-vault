## The rules (owner decisions)

- **Who quarantines:** a Document Steward, for documents of levels they can open; a Restricted Steward, all levels. **Incident-wide quarantine by filter is run by a Restricted Steward only.** Business User, Business Admin, IT Admin, Platform Ops: never.
- **Incident:** every quarantine belongs to a named incident (name, reason, who, when). One document can be quarantined on its own (an incident of one) or added to an open incident.
- **Find for an incident:** filter by received date range, sending system and search (case) fields → Vero gives a **server-side count** → "select all matching" → name the incident → quarantine. Never by file name or content.
- **While quarantined:** nobody can open, print or download the document except reviewers (below). Everyone else sees **"Temporarily unavailable"** (not the level, not why). Search rows and the record panel show it; opening is refused with a QUA code and audited.
- **Review:** any Steward can review quarantined Standard and Confidential documents they can open; Highly Confidential only a Restricted Steward. Review means: open it, then **release** it, or do a **corrective redaction** (existing redaction) and then release.
- **Release:** a single document is released by a reviewer who can open it. **A whole incident** is released only by **request from a Steward or Restricted Steward plus approval by a Business Admin**, through the existing Approvals list as a new request type. Nobody approves their own request; whole-incident requests can't be decided in bulk; they expire like other requests (7 days, configurable). The Business Admin sees the incident name, document count, levels and dates, never content, file names or titles.
- **Retention deletion pauses** while a document is quarantined (like a legal hold). Legal hold and quarantine are independent; both can apply.
- **Exposure report** per incident (Stewards for the levels they can open, Restricted Stewards all): number of documents by level; per document the record's primary identifier, received date, page count; and **who opened, printed or downloaded each one before it was quarantined** (from the audit). CSV export with the reference and a fingerprint, like the other reports.
- **Reasons** (incident reason, release reasons) stay out of the audit trail, kept in the quarantine tables, as for holds and level changes. The audit records who, what, when, the incident ID.
- **Not now:** holding new arrivals into an incident (V2); notifications (platform-core).
- Duplicates: a duplicate arriving for a quarantined document is acknowledged as today and stays quarantined with it.
