# 0052: Quarantine at a million documents

Written: 2026-11-23, by the design chat (follow-up to report 0051). Branch `perf/quarantine-scale` from `release/vero-r7` (at `b4fd5a4`). Vero-only.

**The owner approves:** schema changes the counters need (a Liquibase changeset), code and screen changes below, and running `.\Update-SDV-Schema.ps1 update` on the local `sdv` database (standing approval). No new dependency.

The owner's rule: **no limit** on a quarantine. Correct at a million is not enough; it must also be usable at a million.

1. **Counts kept on the incident** (total, by level, prepared, released), updated as rows are written and released, so the incident list, the incident page and the Approvals row never read the whole incident.
2. **Lists page through the incident** (review list, exposure report screen): pages of 100, oldest first as today, with "next" and the total from the counters. Never load the whole incident into the browser.
3. **The whole-incident release runs in batches** in the background, like preparation: resumable after a restart, never twice, progress shown ("released 300,000 of 1,000,000"). The filter block ends only when every document is released.
4. **The exposure CSV export streams** (row by row), whatever the size; the fingerprint is computed while streaming.
5. **A measured test:** a PostgreSQL test (in the schema check and CI) with **250,000** documents in one incident: blocking is immediate on every path, preparation and release finish, and each screen's API answers within an agreed time. Write the times in the report. Don't raise any test time limit to pass; if a time is too slow, fix the cause. Also run it once locally with **1,000,000** documents (not in CI) and report the times.
