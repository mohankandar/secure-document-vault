## Part A: Keeping documents (finding 21)

1. Current rule as a sentence: "Keep for 7 years" (or "Keep forever"), "Counted from the day each document arrives", "Set by <name or subject>: "<reason>"", "In use since 17 Sep 2026".
2. **When time is up:** "Vero deletes the document for good and records it in the audit. A daily cleanup does this; it last ran today at 07:00 and removed 3 documents." Take the last run from the retention-status data. If the Business admin cannot read it with today's permissions, leave that sentence out and say so in the report; do not change permissions.
3. **Changing the rule:** "A new rule applies to documents that arrive after it starts. Documents already stored keep the rule they arrived with."
4. **New rule** panel: a number plus years, months or days, or **Forever**; a required "Why this changed"; a tick "This change has been approved"; **Start using this rule**. Convert to days for the existing API and show the days in small text ("2,555 days"). State in the report how months are converted.
5. **Earlier rules** from the policy history: Rule, In use (date range or "In use"), Set by, Why. No v1/v2 or "Superseded".

## Part B: Search fields (finding 22)

1. Sending-system picker at the top when there is more than one.
2. One row per field: drag handle, label, a **Searchable** switch, **How it matches** in words (Exact; Starts with, any case; Contains, any case), Edit. The identifier shows "Identifier · always searchable" and "Always". Drag to reorder saves the display order (existing endpoint); remove the separate Reorder dialog.
3. **Edit panel:** Label people see; People can search by it; How it matches with examples ("Starts with "Pat" finds Patel"; "Contains "tel" finds Patel"); "Upper and lower case never matter for names." Field key, type, normalization and version under a folded **Technical details**.
4. **Limits** in words: "Records per page: 25 (most 50)", "Comment length: 2,000 characters", "Tag length: 80 characters". Remove "(current UI)".

## Part C: Record title setting (backend + one migration)

1. Per sending system, the Business admin chooses one or two fields that name a record (e.g. First name + Last name). Store it with the source's search settings; a new migration (019) adds what is needed. Audit the change like other search-field changes.
2. Default when not set: the first preview field, as today. Never an identifier alone (the identifier is shown beside the title anyway).
3. Return the title with each record in search results, Recently viewed and record detail, so Home, Records, the record panel and the viewer all show the same title. Remove the frontend's own title guessing.
4. Tests: default title; chosen title; a chosen field missing on a record falls back to the default; only `CONFIGURE_METADATA_SEARCH` can change it.
