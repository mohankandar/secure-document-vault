## Who sees this

| Part | Seen by |
|---|---|

## What to build

1. **An installation record** (migration 021): one row created only by the setup command (task 0015). It holds the tenant ID, the organization name, when setup ran and from which worksheet (if any). The local seed creates it for local mode, so local mode counts as set up.
2. **Before setup**, the server:
   - answers `GET /api/v1/system/info` with product, version and `setUp: false` (nothing else about the installation);
   - refuses every other API call, including sign-in, session, admin and ingestion, with 503 and a code `SETUP_REQUIRED`, without touching tenant data;
   - Health still works for the installer.
   - Check whether `system/info` needs sign-in today. Anyone not signed in, before or after setup, gets only product, version and `setUp`; active profiles and other details go only to signed-in Tenant IT and Platform operations (About uses them).
3. **The page** (the app shows it instead of sign-in when `setUp` is false):
   - "This installation isn't set up yet";
   - "Vero is running, but no organization has been set up on it. Your installer finishes this with the setup command; see the install guide, "Set up the customer"."
   - "Nobody can sign in or set anything up from this page. That is on purpose: it stops anyone on the network from claiming the installation."
   - **Check again** button and the version.
   - No sign-in button, no form, no way to create anything.
4. Once the record exists, the server and the app behave as today. No restart needed (Check again then leads to sign-in).
5. Install guide: a short "Before setup" note in the clean-install runbook.

## Rules

- No other backend or schema change. No new dependencies.
- There must be no browser or API route that creates the installation record. Only the setup command (task 0015) does.
