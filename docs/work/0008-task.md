## Part A: shared pieces (all areas)

1. **One main-button colour** (change 11): every primary button uses the product's main colour token (Vero green). No blue main buttons anywhere; check every area in light and dark.
2. **A card that fails to load** (finding 24): one shared component. It shows a plain sentence ("Sign-in settings didn't load"), "Vero couldn't reach this setting just now. The rest of the page still works.", a **Try again** button that reloads only that card, and "If it keeps happening, give your IT team this reference: Ref c0ffee42". The reference is the request's correlation ID if the server sent one, otherwise a short random code that is also written to the browser console with the raw error. **No raw error text on screen** (today some cards show "ApiRequestError: …"). Replace every card-level error callout in the admin areas with it; Records and Home may keep their own messages if already plain.
3. **No-access page** (finding 23): "This page isn't part of your role", "Your role is Business user. If you need this page, ask your administrator to add the right role in your company's sign-in system.", buttons "Go to <first area>" and **Sign out**. Shown when someone opens an address their role does not include. Remove "enforced by the server; the interface only reflects it".

## Part B: Business administration

1. **Tab names** (finding 20): People & roles, Roles & permissions, Keeping documents, Search fields. Keep the old addresses (`#/governance/access` etc.) working; new names are labels only.
2. **People & roles:** table with Role, What it is for (one sentence), Name in your sign-in system (the claim value), Can change in Vero ("Yes, in Roles & permissions" / "Fixed"). List Business user, Document steward, Business admin, Tenant IT; **do not list Platform operations** (the provider's role). Below: "To give someone a role, add them to the group with that name in your sign-in system (for example Okta). Vero never stores passwords and does not keep its own list of people, so there is nothing to add here."
3. **Roles & permissions** (finding 19): rows in words (Search records and open documents, Download the PDF, Print, Add tags, Add comments, Permanently redact "Cannot be undone"); columns Business user and Document steward; the always-included action shows "Always on". No capability codes on screen. Footer: "Changes apply the next time each person does something. Every change is recorded in the audit." with Undo changes and Save. Same API as today.
