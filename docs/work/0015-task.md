# Task 0015: The setup command

Written: 2026-11-18, by the design chat. Branch: `feature/install-3`, taken from `feature/install-2`.

Background: the install flow approved by the owner (`docs/design/vero-admin-after.html`, installation boards; customer worksheet "Vero setup worksheet"). Only this command creates the customer and tenant, so nobody on the customer's network can claim an installation from a browser.

The owner approves the backend work below by giving this task. A schema change beyond what's listed needs a stop and report.

## Who uses this

| Part | Used by |
|---|---|
| Setup command | The owner's installer, with the customer's IT administrator |
| Its results in the audit and screens | Tenant IT, Business admin, Platform operations (task 0016) |

## Inputs

1. **From the owner's company:** tenant ID and licence key. Licensing doesn't exist in SDV yet: store the licence key with the installation record as given, show it nowhere except About's technical details (masked), and don't enforce anything. Say so in the report.
2. **From the customer's IT:** organization name; sign-in (Okta issuer, browser client ID, API audience); the group name for each role.
3. **The setup file:** the answers from the customer's worksheet, typed into `vero-setup.yaml`. Add a commented template `docs/install/vero-setup-template.yaml` with:
   - Part A (business): how long to keep documents, with the reason and who approved it; search fields and how each matches; record title;
   - Part B (IT): sending systems (name, source key, fields with kinds, how it signs in and where its secret is kept), if known.
   - **The file never holds a secret.** Refuse any key that looks like one (`secret`, `password`, `token`, `key` with a long value) and say which line.

## What the command does

1. Refuses if the installation is already set up. With `--resume`, it finishes a run that stopped partway.
2. Checks before changing anything:
   - the database schema is current (task 0013);
   - sign-in discovery works for the issuer (use the existing tester);
   - the key service answers and can create this tenant's key.

   On a failed check it stops, says in one plain line what to fix, and changes nothing.
3. Creates the tenant, the sign-in connection (active) and the installation record (task 0014), and saves the role group names wherever SDV keeps them today. If SDV only reads them from environment variables, it checks that those are set, lists them, and says so in the report.
4. Applies Part A:
   - **keeping documents** as the first rule, with the reason;
   - if there's no worksheet answer: **Keep forever**, marked "default, not yet decided by the business".
5. Applies Part B: creates each listed sending system **paused**, with its fields.
6. **Search fields and record title.** They belong to a sending system:
   - If the system is in Part B, apply them now.
   - If it isn't, keep the choices and apply them when Tenant IT adds a sending system with matching field names.
   - With no answer, use the defaults: search by identifier and name; record title = the name field.
7. Audits every item as "set at installation from the customer's worksheet" (or "default at installation"). The actor is the installer's name, given on the command line.
8. Prints a short summary for the install notes: what was set, what was defaulted, and what Tenant IT still has to do.

Provide it as `Setup-SDV.ps1` and `setup-sdv.sh`, running the application package in a setup mode. It uses the app's normal database user and key service settings, never the database owner's password.

## Rules

- No new dependencies. Schema changes only if a value has nowhere to live today. Name them in the report.
- No browser or API route can do any of this.

## Checks

   - the audit entries.
2. The clean-install check from task 0013, extended:
   - schema step, then setup with the template filled for the demo;
   - then the app shows sign-in (no longer "not set up");
   - then local sign-in as each role works.
3. Install guide: the "Set up the customer" section in the clean-install runbook.
