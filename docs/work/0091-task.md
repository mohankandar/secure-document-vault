# 0091: Bind a replaced version to its version (VSEC-21, rest)

Written 2026-11-25 by the design chat. Report 0076: a sealed original can no longer take a document's place, but an earlier version of the same document is bound to the same IDs, so an old ciphertext could be put back in place of the current one. Branch `fix/version-binding` from `release/vero-r7`.

**Approved:** one changeset adding a version column where the stored object's version is kept; the binding header gets version 2 with the version number in it. No reader for header version 1 is needed for documents in production (there are none); local and demo data are re-seeded.

1. Header version 2 carries the document's version; reading checks it against the stored version and refuses another as a failed check.
2. Redaction and every path that writes a new version write the new number in both places in one transaction.
3. Tests: an older version put in place of the current one is refused; every boundary as in 0076; a fixed-bytes test of header 2.
4. `security-findings.md`: VSEC-21 closed. Report `docs/work/0091-report.md` with "No other product's name or behaviour in code" and "Decisions taken". Merge on green `ci-passed`.
