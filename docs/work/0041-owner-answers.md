# Owner answers to plan 0041 (2026-11-22)

Answers to the 15 questions at the end of `0041-plan.md`. Part B follows these. Q4b, Q6 and Q15 were answered by the LexaVault thread (board LV-16, 2026-11-22), below.

1. **Switch-over guide.** The parts that apply (project doc `Platform-Switch-Over-Guide.md`):
   - Item 1, library: move to `platform-bom` + `platform-identity-*` (groupId `com.documentplatform.platform`, Java packages unchanged). Done in 0042.
   - Item 2, schema step: platform Flyway runs beside Liquibase, each with its own history table. For 0041 only `db/platform/identity` (`idn_schema_history`) and `db/platform/licensing` (`lic_schema_history`). Never at start-up. The runtime database user gets DML only.
   - Item 3, no start-up inserts: remove `OidcConnectionBootstrap` and the `local` seed changeset. Demo data comes from demo input files run through `setup`, signed with the development key, plus an app demo step after setup.
   - Item 4, setup: ship `product-roles.json` and a small `setup` wrapper that passes `--keys` and `--product-roles`. It loads the client bindings (setup 6). The customer keys are skipped for now (answer 12). No `LicenceCommand` (licensing waits).
   - Item 6, identity storage: the `idn_` stores (one login connection per customer and product; grants per entity and product). No migration (nothing to keep): drop the old tables (answer 14). Entity UUID derived from the slot ID.
   - Item 7, entity screens: Business Admin activates entities (answer 11, API now); after sign-in, land on the last-used entity; the chooser only when there is none; an entity switcher in the header; every switch audited; the entity name always shown; the upload result names the entity. In 0041 only the minimum (answer 5).
   - "Vero": move from 0.2.0 (done); replace `SDV_AUTH_GROUP_*` with `idn_group_grant`; entity chooser and switcher; rename the "tenant" claim to "entity" and find entity and source from the client ID; replace fixed demo UUIDs with UUIDs derived from the demo slot IDs. (Crypto, licensing, notifications, case fields and the erase log are **not** in 0041.)
2. **Dependencies:** approved: `platform-identity-jdbc`, `platform-identity-testkit` (test), `platform-licensing-testkit` (test, demo licence generator), `platform-setup` (setup wrapper only, never the app) and Flyway (`flyway-core`, `flyway-database-postgresql`) in the schema step only.
3. **Product code:** `SDV`.
4. (a) **Rename `TENANT_IT_ADMIN` to `IT_ADMIN`:** yes, everywhere (code, grants, screens, docs).
   (b) **`PLATFORM_OPERATIONS_ADMIN`** (LV-16 item 3): **no app setting with a group list.** The role stays unused until platform-core offers platform-level grants (planned for v0.3.0 or later). Remove the old `SDV_AUTH_GROUP_PLATFORM_OPERATIONS_ADMINS` setting with the others. Screens and APIs that need the role simply have no one holding it for now; say in the report which ones.

A server-side "last entity" table comes later.

No "test sign-in" in the app until platform-core moves the fetch into an identity module (planned for v0.3.0); connection changes go through setup. The IT Admin's Sign-in tab stays read-only (as already decided: "Sign-in is set during installation by your installer").
