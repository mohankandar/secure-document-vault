# 0096: Second independent security review of Vero (findings only)

Written 2026-11-27 by the SDV design chat. **After 0082 is merged.** Branch `review/security-2` from `release/vero-r7`. **Read only: change no product code.** Same rules as 0061 (detail stays local; the repo gets the plain-terms list).

Review Vero **as if you didn't build it** (don't trust earlier reports; check the code and run it where that proves a point). Focus on what changed since 0061 (merge b6a05fe), then re-check the 0061 fixes still hold:
- the move to platform-core 1.x and Spring Boot 4.2: sign-in, machine tokens, audiences, CSRF, CORS, what the BOM changed by default;
- keys and crypto (0076, 0091): customer keys, batch opening (1.1.x), names in result lists through the key service, what is logged, key errors;
- licensing (0075, 0090): can a seat, a level or a feature be had without a valid licence; tampered or expired licence files;
- integration E–I (0077–0082): new endpoints and screens, entity isolation on each, the erase log (folder permissions, what it holds, can it be changed or read by the wrong person), notifications (what a message may contain: no document content, no names above the recipient's level), approvals from messages (one-time, bound to the approver, expiry, replay, "already decided");
- monitoring (0074): health and metrics endpoints reachable without sign-in, and what they show;
- the owner scripts and setup command (0083, 0095): secrets typed, passed, stored or printed;
- dependencies (Maven and npm) against known advisories; CI and workflow permissions.
