## Part A: one search bar instead of the left search panel

Replace the left "Find a record" panel in `src/r7/Workspace.tsx` with one search bar across the top of the Records area (design screen 2).

1. **The box.** The server has no free-text search today, so the box does not pretend to search "anything". Route what the person types:
   - if it matches an identifier field of the current source (for example digits for a contract number, after that field's normalization), search that identifier with its configured match;
   - otherwise search the first searchable text field whose match is Contains or Starts with (for example Borrower name).

   The placeholder names those fields from the source's own labels ("Contract number or borrower name"), never hard-coded words. Say in the report how the routing chooses, and which cases it cannot handle.
2. **Applied filters show as chips** inside the bar ("Borrower name contains lee ×"). Removing a chip searches again.
3. **Filters button** with the count of active filters, and **Clear**.
4. Keyboard: Enter searches; Escape clears the box; the bar is reachable by Tab right after the top bar.

## Part B: the Filters panel

Opens from the Filters button (design screen 3): a panel under the bar on desktop, a full-screen sheet on phones.

1. **Source**: shown only when there is more than one source.
2. One field per searchable field of the source, in the configured display order, each with its match label (Exact, Contains, Starts with) as today.
3. **Last updated** with visible **From** and **To** labels (change 8).
4. Footer hint: "Up to 25 records per page. You only see records your role allows." The number must come from the same setting the search uses, not typed text (change 8).
5. **Show results** applies and closes; **Clear** empties the fields.

## Part C: the results

A full-width table (design screen 2):

1. Columns: the identifier(s) once, then the preview fields the server already sends (`metadataPreview`, for example Borrower, Loan type) in display order, Documents (`availableDocumentCount`), Updated (relative time).
2. A record with an incomplete submission shows a warning badge in the row. `RecordSummary` only says that it is incomplete, so the row says "Missing documents"; the counts appear in the record panel.
3. Header: "N records · source name" and the sort ("Sorted by last updated"). Paging as today, with "Showing X of Y" wording where the server allows.
4. Selecting a row highlights it and opens the record panel; arrow keys move between rows; Enter opens.
5. Empty states in plain words: before any search ("Search by contract number or borrower name"), no results (what to try next).

## Part D: the record panel

On the right of the results (design screen 2), replacing today's inspector:

1. Title: the first preview field's value (for example the borrower's name); the identifier sits in the identifier box below it (task 0001's layout).
2. Incomplete submission: "2 of 4 documents received", and the names of the missing documents from `missingSourceDocumentIds`.
3. Documents with page count where known and received date; Details; Recent activity (as today).
4. **Open documents** button (`VIEW_PDF`).
5. Close with × or Escape; the selection stays in the list.
