## Part A: Overview (change 9)

1. One opening sentence: "2 things need attention. 4 documents did not arrive properly, and storage primary-a is 82% full." or "Everything is working."
2. Four tiles, each opening its tab: **Problems** (count and kinds), **Storage** (fullest volume, "warns at 80%, stops at 95%"), **Services** ("All working" or which one isn't), **Cleanup** ("3 deleted today", next run).
3. **Latest activity:** the last 3–5 audit sentences (task 0011 patterns), with "All activity →" to Audit.
4. No terms such as "attention submissions" or raw status codes.

## Part B: Storage, read-only (change 9)

Table: Volume, Role (In use / Standby), How full, Can store new documents ("Yes", "Yes, but nearly full", "No: full", "No: can't reach the folder"). Below: "What to do: ask the customer's Tenant IT to add space to primary-a or add a volume. At 95% Vero switches new documents to primary-b by itself." (or without the switch sentence if there's no standby). Paths, thresholds, last check and write-test result under **Technical details**. No edit buttons.

## Part C: Health (change 9)

1. Header "Checked 2 minutes ago" and **Check now** (replaces Refresh).
2. Services table: Service, What it does, Status:
   - Vero, "The application itself";
   - Database, "Keeps records, settings and the audit";
   - Key service, "Locks and unlocks stored documents (Vault)".
3. When one is down, say what stops working and what to check. For example: "Key service isn't answering. Nobody can open documents and new deliveries wait. Check that Vault is running and unsealed." Write one such sentence per service, in one file.
4. **Automatic cleanup** as a sentence: when it last ran, what it deleted, the next run. A failed run shows in red with what to do.
5. Component names, response times and raw cleanup fields go under **Technical details**. No ISO timestamps on screen.

## Part D: About this installation (change 10)

1. One page replacing Tenant IT › Environment and Platform operations › Configuration; old addresses open it. Tab **About** in both areas.
2. Facts:
   - Product (name and version)
   - Status
   - Installed ("On your own servers" or "Hosted"; from the deployment mode the server reports, or leave out and say so)
   - Organization (tenant display name)
   - Sign-in (provider name)
   - Checked
3. **Copy details for support:** these facts plus the technical details as plain text. No documents and no personal data. Technical details (active profiles, build, last correlation ID) are folded.

## Part E: finding 13

Remove `PLATFORM_CONFIGURATION` from `Capability` and `RoleCapabilities`, and update `FinalRoleMatrixTest`. First check that no stored data, token mapping or frontend code refers to it; if anything does, stop and report.

## Part F: Sign-in is read-only (finding 16, decided 2026-11-18)

Sign-in is set by a script the installer runs, never through screens (owner decision). So the Tenant IT **Sign-in** tab becomes read-only:
1. Show the sign-in in use in words: provider (e.g. Okta), its address, the client ID, the role groups it maps, when it was last changed and by whom.
2. Remove edit, draft, test, activate and rollback from the screen. Add: "Sign-in is set during installation by your installer. To change it, contact your Vero support team."
3. Leave the backend endpoints as they are for now (the shared install work decides their future); say in the report which ones the screen no longer uses.
