# 0050: Sealed audit report

Written: 2026-11-22, by the design chat. Design: `SDV-Sensitivity-and-Quarantine.md` section 5 and 3.6. Branch `feature/sealed-audit` from `release/vero-r7` **after 0049 is merged**. Vero-only.

**The owner approves:** a Liquibase changeset (the report register table, and the database rules below), a new audit event, API endpoints and screens. No new dependency.

## The rules (owner decisions)
- **No auditor role.** Auditors get no access to Vero. A **Business Admin or IT Admin** generates the sealed audit report and hands it over, so nobody can forge anything.
- **The audit trail is append-only.** Make it hold at the database level: the runtime user has no UPDATE or DELETE on the audit table, and a trigger refuses both for anyone. Retention of audit rows (if any rule deletes old rows) is out of scope; say in the report what exists today.
- **The report:** for a date range (and optional filters already on the Audit page), exported as **PDF for people and CSV for machines**, both stamped with who generated it, when, the range and filters, the row count, and a **SHA-256 fingerprint** of the CSV content. Document IDs and record primary identifiers, **never content, file names or titles**; reasons stay out as today.
- **Register:** every generated report is recorded (who, when, range, filters, row count, fingerprint), and its generation is audited.
- **Verify:** a Business Admin or IT Admin can check a report: upload the CSV (or paste its fingerprint), and Vero says whether it matches a registered report and when it was made. A changed file fails.
- Screens: an "Audit report" action on the Audit page (R7 look, as Reports' exports), the register list, and Verify. Error wording through the 0044 helper; new codes in the `AUD` area.

Tests: append-only holds (UPDATE and DELETE refused, PostgreSQL test in CI); report contents never include content; fingerprint matches the CSV; verify passes for an unchanged file and fails for a changed one; role checks (Steward, Business User refused). `npm test`, full build, both schema checks, `ui:capture` with new steps and screenshots.
